5. Working of the application
1. The user opens the application in a browser.
2. The frontend displays a form and records table.
3. The user enters the required details.
4. JavaScript sends the data to the backend using the Fetch API.
5. Express receives the request through an API endpoint.
6. The backend executes the required SQL query.
7. MySQL stores or retrieves the information.
8. The backend sends a response in JSON format.
9. JavaScript updates the webpage without manually refreshing it.

8. JavaScript – Connecting frontend and backend
JavaScript handles user actions and communicates with the backend using the Fetch API.

Important code for adding a record:
document.getElementById("studentForm")
.addEventListener("submit", async function(e) {

    e.preventDefault();

    const student = {
        name: document.getElementById("name").value,
        email: document.getElementById("email").value,
        course: document.getElementById("course").value
    };

    const response = await fetch("/students", {
        method: "POST",
        headers: {
            "Content-Type": "application/json"
        },
        body: JSON.stringify(student)
    });

    if (response.ok) {
        alert("Student added successfully");
        loadStudents();
    }
});


Explanation:
- addEventListener() detects form submission.
- preventDefault() prevents page refresh.
- fetch() sends data to the backend.
- POST specifies the operation.
- JSON.stringify() converts the object into JSON.
- loadStudents() refreshes the displayed records.

10. REST API operations
These are the most important backend lines to remember.

A. CREATE – Insert a record
app.post("/students", (req, res) => {
    const {name, email, course} = req.body;

    const sql =
    "INSERT INTO students(name,email,course) VALUES(?,?,?)";

    db.query(sql, [name,email,course], (err, result) => {
        if (err) return res.status(500).json(err);

        res.json({message: "Record inserted"});
    });
});


B. READ – Display all records
app.get("/students", (req, res) => {
    db.query("SELECT * FROM students", (err, result) => {
        if (err) return res.status(500).json(err);

        res.json(result);
    });
});


C. UPDATE – Modify a record
app.put("/students/:id", (req, res) => {
    const {name, email, course} = req.body;

    const sql =
    "UPDATE students SET name=?, email=?, course=? WHERE id=?";

    db.query(sql, [name,email,course,req.params.id],
    (err, result) => {
        if (err) return res.status(500).json(err);

        res.json({message: "Record updated"});
    });
});


D. DELETE – Remove a record
app.delete("/students/:id", (req, res) => {
    db.query("DELETE FROM students WHERE id=?",
    [req.params.id], (err, result) => {
        if (err) return res.status(500).json(err);

        res.json({message: "Record deleted"});
    });
});


Finally, start the server:
app.listen(3000, () => {
    console.log("Server running on port 3000");
});


Important explanation for faculty:
HTTP method	Operation	Purpose
POST	Create	Insert new record
GET	Read	Display records
PUT	Update	Modify existing record
DELETE	Delete	Remove a record

The ? placeholders are used for parameterized queries, which help prevent SQL injection.
11. MySQL – Database design
MySQL is a relational database used to store application information.

Create database and table:
CREATE DATABASE student_db;

USE student_db;

CREATE TABLE students (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE,
    course VARCHAR(50)
);


Important SQL operations:
-- Insert
INSERT INTO students(name,email,course)
VALUES('Rahul','rahul@gmail.com','CSE');

-- Display
SELECT * FROM students;

-- Update
UPDATE students
SET course='ECE'
WHERE id=1;

-- Delete
DELETE FROM students
WHERE id=1;

-- Search
SELECT * FROM students
WHERE name='Rahul';


Explanation:
- Primary key uniquely identifies each record.
- AUTO_INCREMENT automatically generates IDs.
- NOT NULL prevents empty values.
- UNIQUE prevents duplicate email addresses.
- SQL queries perform database operations.

Page 4 – Docker containerization and deployment
12. Docker – Containerization
Docker is a platform used to package an application and its dependencies into containers.

It helps the application run consistently across different environments.

A. Dockerfile
FROM node:22

WORKDIR /app

COPY package*.json ./

RUN npm install

COPY . .

EXPOSE 3000

CMD ["node", "server.js"]


Explanation:
- FROM selects the Node.js base image.
- WORKDIR creates the working directory.
- COPY copies application files.
- RUN npm install installs dependencies.
- EXPOSE documents the application port.
- CMD starts the backend server.
B. Docker Compose

Docker Compose is used to run multiple containers together.
services:
  app:
    build: .
    ports:
      - "3000:3000"
    depends_on:
      db:
        condition: service_healthy

  db:
    image: mysql:8
    environment:
      MYSQL_ROOT_PASSWORD: root123
      MYSQL_DATABASE: student_db
    volumes:
      - dbdata:/var/lib/mysql
      - ./database.sql:/docker-entrypoint-initdb.d/database.sql:ro
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 5s
      timeout: 5s
      retries: 10

volumes:
  dbdata:


Explanation:
- app runs the Node.js application.
- db runs the MySQL database.
- ports maps the host port to the container port.
- depends_on waits for database health.
- volumes preserve database information and initialize the database.
13. Important Docker commands
# Build and start containers
docker compose up --build -d

# Display running containers
docker ps

# View application logs
docker compose logs app

# Stop containers
docker compose down

# Stop and remove containers and database volume
docker compose down -v


Note: The last command deletes the persistent database volume, so do not use it when you need to retain your records.

16. How to adapt the same application to any use case
This is the most important part of your preparation.

You don't need to change the entire application. Change the entity name, input fields, table name and SQL columns according to the question.
Use case	Database table	Important fields
Student Management	students	name, email, course, age
Employee Management	employees	name, email, department, salary
Hospital Management	patients	name, age, disease, doctor
Library Management	books	title, author, category, quantity
Product Management	products	name, price, category, stock
Appointment Booking	appointments	patient_name, doctor, date, time
Vehicle Management	vehicles	vehicle_number, model, owner
Event Management	events	event_name, date, venue, capacity

CREATE TABLE employees (

app.post("/employees", (req, res) => {
